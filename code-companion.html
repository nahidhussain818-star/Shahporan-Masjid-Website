1. The page skeleton

What you see

Every webpage starts with the same boilerplate. This is the "frame" of your site before any content goes in.

The code

<!doctype html>
<html lang="en" class="scroll-smooth">
<head>
  <meta charset="utf-8"/>
  <meta name="viewport" content="width=device-width, initial-scale=1"/>
  <meta name="description" content="Shahporan Masjid..."/>
  <meta name="theme-color" content="#0e5c3b"/>
  <title>Shahporan Masjid & Islamic Centre — London</title>
</head>
<body>
  <!-- everything visible goes here -->
</body>
</html>

What's happening

  1. <!doctype html> tells the browser "this is modern HTML, use proper rules". Without it, browsers fall back to weird legacy behaviour.
  2. lang="en" tells screen readers and search engines the page is in English.
  3. class="scroll-smooth" is a Tailwind utility — when you click an anchor link like #prayer-times, the page glides there instead of jumping.
  4. The charset tag tells the browser how to interpret characters (so Arabic, accents, and emoji all render correctly).
  5. The viewport tag is what makes the page work on phones at all. Without it, mobile browsers render at desktop width and zoom out — making everything tiny.
  6. theme-color sets the colour of the address bar on mobile browsers — your green masjid colour bleeds into the browser chrome on Android Chrome / iOS Safari.
  7. <title> is what appears in the browser tab and in Google search results.

2. Tailwind setup & custom design tokens

What you see

Every class="..." in the masjid site that looks cryptic — bg-masjid-700, md:grid-cols-6, dark:text-gold-400 — comes from Tailwind. The setup at the top of the file defines a colour palette specific to this site.

The code

<script src="https://cdn.tailwindcss.com"></script>
<script>
  tailwind.config = {
    darkMode: 'class',
    theme: { extend: {
      colors: {
        masjid: { 600: '#0e5c3b', 700: '#0a4a2f', ... },
        gold:   { 500: '#c9a14a', ... }
      },
      fontFamily: {
        display: ['"Cormorant Garamond"', 'serif'],
        arabic:  ['"Amiri"', 'serif']
      }
    } }
  }
</script>

What's happening

  1. The first <script> loads Tailwind directly from a CDN. No build step needed — perfect for learning.
  2. darkMode: 'class' tells Tailwind: "switch to dark mode when the <html> tag has a dark class on it." (Other option is 'media' which follows the OS — but then users can't override it.)
  3. theme.extend.colors registers custom colours so you can use bg-masjid-600 in classes — without it, only Tailwind's defaults (blue, red, etc.) are available.
  4. fontFamily registers font names so font-display and font-arabic classes work.

Try this

Open index.html, change '#0e5c3b' (the masjid green) to '#7c2d12' (deep red), save, reload. The whole site shifts colour. You've just changed your design system in one place.

3. Dark mode toggle ⭐

What you see

Tap the moon icon in the top bar. The whole site flips to dark theme. Close your browser, come back tomorrow — it remembers your choice. New visitors get whatever their OS is set to.

The code

const root = document.documentElement;
const savedTheme = localStorage.getItem('spm-theme');

if (savedTheme === 'dark' ||
   (!savedTheme && window.matchMedia('(prefers-color-scheme: dark)').matches)) {
  root.classList.add('dark');
}

document.getElementById('theme-toggle').addEventListener('click', () => {
  root.classList.toggle('dark');
  localStorage.setItem('spm-theme', root.classList.contains('dark') ? 'dark' : 'light');
});

What's happening

  1. document.documentElement is a fancy way of saying "the <html> tag". We grab a reference to it so we can add/remove classes on it.
  2. localStorage.getItem('spm-theme') reads a saved value from the browser's persistent storage. localStorage survives reloads, restarts, even system shutdowns — until the user clears their browser data.
  3. The big if: "If they previously chose dark, OR if there's no saved choice AND their OS is currently in dark mode" — add the dark class. window.matchMedia('(prefers-color-scheme: dark)') reads the OS setting.
  4. addEventListener('click', ...) attaches a function that runs every time the button is clicked.
  5. Inside the click handler: classList.toggle('dark') adds the class if missing, removes it if present.
  6. Then we save the new state to localStorage so it persists. The ? : bit is a ternary — "if X, return A, else B".

Concepts at play

  • document.getElementById & document.documentElement — finding elements
  • classList — the modern way to add/remove/toggle classes
  • localStorage — persistent in-browser key/value storage
  • addEventListener — responding to user actions
  • Arrow functions () => {}
  • The ternary operator condition ? a : b
  • window.matchMedia — querying CSS media queries from JS

Try this

In Chrome DevTools, go to Application → Local Storage → your site URL. You'll see spm-theme as a key. Edit it manually, reload the page, and watch the theme change. That's persistent storage in action.

4. Mobile hamburger menu

What you see

On narrow screens the desktop nav hides and a hamburger button (three lines) appears. Tap it and a menu slides down. Tap a link and it auto-closes.

The code

const menuBtn = document.getElementById('menu-btn');
const mobileMenu = document.getElementById('mobile-menu');

menuBtn.addEventListener('click', () => mobileMenu.classList.toggle('open'));

mobileMenu.querySelectorAll('a').forEach(a =>
  a.addEventListener('click', () => mobileMenu.classList.remove('open'))
);

What's happening

  1. Grab the hamburger button and the menu container.
  2. When the button is clicked, toggle the open class on the menu.
  3. The CSS handles the actual animation: #mobile-menu has max-height: 0 by default, and .open raises it to 600px with a transition — smooth slide-down.
  4. querySelectorAll('a').forEach(...) grabs every link inside the menu and adds a click listener to each, so the menu auto-closes after navigation.

5. Mobile bottom navigation

What you see

On phones, a bar pinned to the bottom of the screen with five icons. The active section glows gold and gets an indicator bar at the top of its tab as you scroll.

The code

const bottomNavItems = document.querySelectorAll('.bottom-nav-item');
const bottomNavTargets = { 'home':'home', 'prayer-times':'prayer-times',
                           'events':'events', 'donate':'donate', 'contact':'contact' };

const bottomNavObs = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (e.isIntersecting && bottomNavTargets[e.target.id]) {
      bottomNavItems.forEach(b =>
        b.classList.toggle('active', b.dataset.target === e.target.id)
      );
    }
  });
}, { rootMargin: '-30% 0px -60% 0px' });

What's happening

  1. IntersectionObserver is a browser API that watches elements and tells you when they enter or leave the viewport. Much more efficient than listening to scroll events.
  2. rootMargin: '-30% 0px -60% 0px' shrinks the trigger zone so only the section currently in the middle-ish of the screen counts as "active".
  3. When a tracked section becomes visible, we loop through every bottom-nav item and add the active class only to the one matching that section.
  4. b.dataset.target reads the data-target attribute from the HTML (a clean way to associate metadata with elements).

6. Gregorian + Hijri date display

What you see

In the top bar: "Tuesday, 13 May 2026" alongside the Hijri equivalent. Updates every minute.

The code

function updateDates() {
  const now = new Date();

  document.getElementById('gregorian-date').textContent =
    now.toLocaleDateString('en-GB', {
      weekday:'long', day:'numeric', month:'long', year:'numeric'
    });

  try {
    const hijri = new Intl.DateTimeFormat('en-TN-u-ca-islamic-umalqura', {
      day:'numeric', month:'long', year:'numeric'
    }).format(now);
    document.getElementById('hijri-date').textContent = hijri;
  } catch(e) { /* old browsers — silently skip */ }
}

updateDates();
setInterval(updateDates, 60_000);

What's happening

  1. new Date() creates a JS Date object representing right now.
  2. toLocaleDateString('en-GB', {...}) formats it in British English with weekday name, day number, month name, year — "Tuesday, 13 May 2026".
  3. The Hijri date uses Intl.DateTimeFormat with the locale string 'en-TN-u-ca-islamic-umalqura' — which means "English text, Tunisia regional rules, using the Islamic Umm al-Qura calendar". Browser does the conversion.
  4. The try / catch protects against very old browsers that don't support that calendar — they just skip silently.
  5. setInterval(updateDates, 60_000) runs the function every 60,000ms (1 minute), so the date rolls over at midnight without a reload.

7. Fetching prayer times ⭐

What you see

On page load, six prayer-time cards populate with today's Fajr, Sunrise, Dhuhr, Asr, Maghrib and Isha. The data comes from a public API.

The code

async function fetchPrayerTimes() {
  // 1. Manual override (most accurate)
  if (window.MASJID_MANUAL_TIMES) return window.MASJID_MANUAL_TIMES;

  // 2. Otherwise hit the Aladhan API
  const today = new Date();
  const dd = String(today.getDate()).padStart(2, '0');
  const mm = String(today.getMonth() + 1).padStart(2, '0');
  const yyyy = today.getFullYear();

  const url = `https://api.aladhan.com/v1/timings/${dd}-${mm}-${yyyy}` +
              `?latitude=51.5292&longitude=-0.0686` +
              `&method=3&school=1`;

  const r = await fetch(url);
  const j = await r.json();
  return j.data.timings;
}

What's happening

  1. async marks this function as one that does asynchronous work — it returns a Promise.
  2. First we check: did the user paste in manual times? If so, use those — no network call needed.
  3. Otherwise we build the URL. Today's date gets split into day/month/year. padStart(2, '0') turns 5 into "05" so the URL matches the API's format.
  4. The URL also includes coordinates (Hackney), calculation method (3 = Muslim World League), and school (1 = Hanafi).
  5. await fetch(url) pauses execution until the server responds. await can only be used inside async functions.
  6. await r.json() parses the response body as JSON (converting the text into a JS object).
  7. We return j.data.timings — the part of the response that contains the actual prayer times.

Concepts at play

  • Asynchronous JS — code that waits for slow things (network, files) without freezing the page
  • Promises and the modern async / await syntax
  • The Fetch API — the modern way to call URLs from JS
  • JSON — the universal data format used by virtually every web API
  • Template literals (the `backticks`) with ${interpolation}
  • String methods: padStart, split

Try this

Paste this into your browser's address bar: https://api.aladhan.com/v1/timings/13-05-2026?latitude=51.5292&longitude=-0.0686&method=3&school=1 — you'll see the raw JSON the API returns. That's exactly what your JS receives.

8. Rendering prayer cards

What you see

The six prayer cards in the grid. The "next" prayer card is highlighted in green with white text.

The code

function renderPrayerCards(times) {
  const container = document.getElementById('prayer-cards');
  container.innerHTML = '';
  const next = nextPrayerInfo(times);

  PRAYERS.forEach(p => {
    const isNext = next && next.key === p.key;
    const beginTime = times[p.key].slice(0, 5);

    const card = document.createElement('div');
    card.className = 'card prayer-card ' + (isNext ? 'next' : '');
    card.innerHTML = `
      <div class="label">${p.label}</div>
      <div class="time">${fmt(beginTime)}</div>
    `;
    container.appendChild(card);
  });
}

What's happening

  1. Get the container, then empty it (innerHTML = '') — clears any existing skeleton cards.
  2. Figure out which prayer is next so we can highlight it.
  3. For each prayer (Fajr, Sunrise, Dhuhr, ...): document.createElement makes a new <div> in memory.
  4. Set its class — including next if this is the next prayer (which makes it green via CSS).
  5. Set its inner HTML using a template literal — values from p and beginTime get inserted via ${...}.
  6. appendChild attaches the new card to the container, making it appear on the page.

9. Live next-prayer countdown ⭐

What you see

The top bar shows "Next: Asr in 02:34:17" — the seconds tick down in real time. When a prayer time passes, it automatically rolls over to the next one.

The code

function nextPrayerInfo(times) {
  const now = new Date();
  const list = ['Fajr', 'Dhuhr', 'Asr', 'Maghrib', 'Isha'];

  for (const k of list) {
    const [h, m] = times[k].slice(0, 5).split(':').map(Number);
    const d = new Date(now);
    d.setHours(h, m, 0, 0);
    if (d > now) return { key: k, at: d };
  }
  // All today's prayers passed — next is tomorrow's Fajr
  const [h, m] = times.Fajr.slice(0, 5).split(':').map(Number);
  const d = new Date(now);
  d.setDate(now.getDate() + 1);
  d.setHours(h, m, 0, 0);
  return { key: 'Fajr', at: d };
}

function startCountdown(times) {
  function tick() {
    const next = nextPrayerInfo(times);
    const diff = next.at - new Date();
    if (diff <= 0) { loadPrayer(); return; }

    const h = Math.floor(diff / 3_600_000);
    const m = Math.floor((diff % 3_600_000) / 60_000);
    const s = Math.floor((diff % 60_000) / 1000);

    document.getElementById('next-prayer-name').textContent = next.key;
    document.getElementById('next-prayer-countdown').textContent =
      `${pad(h)}:${pad(m)}:${pad(s)}`;
  }
  tick();
  setInterval(tick, 1000);
}

What's happening — nextPrayerInfo

  1. Get the current time.
  2. Loop through the five obligatory prayers (sunrise is skipped — it's a time but not a prayer to count down to).
  3. For each, split the time string "16:30" into [16, 30] and turn those into numbers with .map(Number).
  4. Make a Date for today at that hour/minute.
  5. If that Date is still in the future, return it — we've found the next prayer.
  6. If we get past the loop, all today's prayers have passed. Build a Date for tomorrow's Fajr instead.

What's happening — startCountdown

  1. diff = next.at - new Date() — subtracting two Dates gives you milliseconds between them.
  2. If diff <= 0, a prayer time just passed. Call loadPrayer() to refetch — handles day rollover and gets us a fresh "next prayer".
  3. Convert milliseconds to hours / minutes / seconds with division and modulo:
    • 1 hour = 3,600,000 ms
    • 1 minute = 60,000 ms
    • 1 second = 1,000 ms
  4. Math.floor rounds down.
  5. Write the values into the page via textContent.
  6. setInterval(tick, 1000) calls tick() every second — that's what makes the seconds visibly count down.

Concepts at play

  • JS Date objects and arithmetic
  • Modulo (%) for breaking numbers into units
  • setInterval for repeated execution
  • Destructuring (const [h, m] = ...)
  • Array methods: split, map
  • Template literals

10. Scroll-reveal animation

What you see

As you scroll down, each section fades in and slides up slightly into place — rather than being blunt and just appearing.

The code

/* CSS */
.reveal { opacity: 0; transform: translateY(16px); transition: opacity .7s, transform .7s; }
.reveal.visible { opacity: 1; transform: none; }

/* JS */
const observer = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      e.target.classList.add('visible');
      observer.unobserve(e.target);
    }
  });
}, { threshold: 0.1 });

document.querySelectorAll('.reveal').forEach(el => observer.observe(el));

What's happening

  1. CSS sets every .reveal element to opacity: 0 and 16px below where it should be — invisible and slightly down.
  2. Adding the class .visible brings them back to opacity: 1 and transform: none. The transition animates the change smoothly over 0.7 seconds.
  3. IntersectionObserver watches elements and fires a callback when their visibility changes.
  4. When an element scrolls into view (e.isIntersecting is true), we add the visible class — triggering the CSS animation.
  5. observer.unobserve(e.target) tells the browser "stop watching this one" — no point listening after it's already revealed.
  6. threshold: 0.1 means "fire when 10% of the element is on screen".

12. Events & Downloads rendering (JS templating)

What you see

The Events and Downloads sections show cards generated from JS arrays. To add/change one, you edit the data — not the HTML.

The code

window.MASJID_EVENTS = [
  { title: "Friday Khutbah", date: "Recurring", time: "1:20 PM", description: "...", type: "Weekly" },
  { title: "Tafsir Circle", date: "Every weekday", ... },
  ...
];

function renderEvents() {
  const list = document.getElementById('events-list');
  list.innerHTML = window.MASJID_EVENTS.map(ev => `
    <div class="card">
      <span class="type">${ev.type}</span>
      <span class="date">${ev.date}</span>
      <h4>${ev.title}</h4>
      <p>${ev.description}</p>
    </div>
  `).join('');
}

What's happening

  1. Define an array of objects — each object is one event.
  2. .map(ev => \`...\`) transforms each object into a string of HTML, with values injected via ${}.
  3. .join('') glues all those strings together into one big string.
  4. Setting list.innerHTML = ... replaces all the container's children with the new HTML.
  5. To add an event: just push a new object into the array. The HTML doesn't change.

Concepts at play

  • Arrays of objects — fundamental JS data shape
  • .map() — transform one array into another
  • Template literals with ${} interpolation
  • .join('') — array → string
  • The "data drives the view" mental model — a stepping stone to React

13. Contact form (mailto)

What you see

Fill in name, email, subject, message → hit Send. The user's email client opens with the message pre-filled, addressed to the masjid.

The code

document.getElementById('contact-form').addEventListener('submit', (e) => {
  e.preventDefault();
  const f = new FormData(e.target);
  const subj = encodeURIComponent(f.get('subject') || 'Website enquiry');
  const body = encodeURIComponent(
    `From: ${f.get('name')} <${f.get('email')}>\n\n${f.get('message')}`
  );
  window.location.href = `mailto:shahporanmasjid24@gmail.com?subject=${subj}&body=${body}`;
});

What's happening

  1. Listen for the form's submit event.
  2. e.preventDefault() stops the browser from doing its default (which would be: navigate to a server URL and try to send the form there). We're handling it ourselves.
  3. new FormData(e.target) reads every named field from the form into an object we can query.
  4. encodeURIComponent escapes any characters that would break a URL (spaces become %20, etc).
  5. We build a mailto: link with the subject and body pre-filled.
  6. Setting window.location.href to the mailto link tells the OS "open the default email app with this content".

Try this

Type mailto:test@example.com?subject=Hello&body=Test into your browser's address bar — the same trick. The browser hands it off to whatever app you've set as your default email client.

15. CSS variables & theming

What you see

The decorative geometric background pattern is one colour in light mode and a different colour in dark mode. It changes without any JavaScript — pure CSS.

The code

:root {
  --pattern-color: rgba(14, 92, 59, 0.06);
}
.dark {
  --pattern-color: rgba(216, 183, 102, 0.08);
}

.geo-bg {
  background-image:
    radial-gradient(circle at 20% 10%, var(--pattern-color) 0 1px, transparent 1.5px),
    ...
}

What's happening

  1. :root means "the <html> tag" — it's where we define global CSS variables.
  2. --pattern-color is a custom property (CSS variable). Any rule below can read it with var(--pattern-color).
  3. When the dark class is on <html>, the second rule overrides the value to gold instead of green.
  4. Because .geo-bg uses var(--pattern-color), it automatically picks up whichever value is currently active.
  5. One variable, two themes, zero JS. This is how the JS dark-mode toggle ends up cascading visually through the whole page.
